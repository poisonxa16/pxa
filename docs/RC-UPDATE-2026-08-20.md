# Update sheet — v2026.08.11 → RC (unified build)

Baseline: `v2026.08.11` (`1995cd9`, "dense arch support, recipient-harmony chat parsing,
sm_70 attention lever") — the last public release.
Head: `pxa/unified-safe`, the single unified truth branch.

Every branch that existed on the box was merged into this line one at a time, each merge
followed by a compile. A blanket union of all of them (the earlier `pxa/unified`) produced
duplicated kernel code that would not build and gave no way to attribute the damage;
`pxa/unified-safe` is that work redone under a gate. Only two files were ever unique to the
broken union (`src/graphs/build_dspark.cpp`, `src/llama-dspark-sched.cpp`) and both arrive
here through `dspark-port` proper.

The **hyper-connection fusion** on deepseek4 is the single largest graph win in this
release: **32,077 → 7,639 graph nodes per forward**.

## 2. PXQ codec

- **PXQ2 v3 book** (`PXA_PXQ2_V3`, default OFF) — model-family Lloyd refit (LM4R) on the
  target family's own pxq2-tier expert weights. Held-out: **−7.9% raw / −9.3%
  population-weighted** error, uniform across weight bands. The pinned-exact-zero variant
  was fit, evaluated, and **failed** its pre-registered gate — recorded, not shipped.
- **PXQ2 v2 book** (`PXA_PXQ_CEIL_V2`) — the ceiling fix. Pure rescale of the frozen LM4 so
  `max|book| == 1.0`, restoring the representable ceiling from `0.697×anchor` to
  `0.987793×anchor` (PXQ4/PXQ6 parity). The v1 book stays the default so every PXQ2 file
  already shipped still decodes byte-identically.
- `PXQ_CANON_v2` chained-FFMA accumulation: **+5.7%** drafted decode (122B / 4×P100).
- `PXA_PXQ6_SHFL` **+4.1%**, bit-exact — codebook off the LSU onto the shuffle unit.
- `PXA_PXQ3_PAIRLUT` **+3.7%**, bit-exact, MoE down-split lever.
- `FUGSPLIT` — dense PXQ up/gate decode as two plain MMVQ launches: **sm_70 +14.7%**, bit-identical.
- Three env-gated codec fixes, all default OFF, so a stock build is byte-identical to before.
- Quantizer now resolves `pxa.pxq.backbone_map` from the run's **actual** per-role decisions
  rather than four hardcoded strings, and records the raw overrides.
- `ggml_validate_row_data` accepts the PXA slab types (they used to fail validation).
- `kv-override` gained a `uint:` tag so UINT32 metadata can be baked at quantize time.

## 3. CUDA / performance

Everything below is measured on our own rigs and recorded in `docs/lab/LEVERS.md`.

- **122B / P100 decode 27.69 → 33.20 tok/s** with a correctness gate attached.
- `PXA_FA_TILE_VOLTA` — sm_70 down the tile path (default off): **+6.9% prefill**.
- `PXA_F32PREC_F16GEMM` — PREC_F32 dense GEMMs take f16-input/fp32-accumulate tensor-core GemmEx.
- sm_60: GQA head-packed D=256 vec flash-attention, shared-memory query staging, FA D=256
  V-pass 4-way ILP, 128-thread float4 router GEMV.
- `PXA_AUTO_SPEC` — arms the measured-best self-speculation drafter per family.
- Recorded **negative** results, kept so they are not re-attempted: FUSERED (loss on both
  arches, default OFF), `PXA_MTP_PREFETCH` (null on the 2×V100 split rig), ROWX2 (null),
  `PXA_PXQ_REDUCE_BLK` (null), sm_60 fast-fp16 carve-out (**−49%/−58% prefill**, rejected).

### Correctness fixes worth calling out
- **WMMA half-accumulate mask query-row stride** (`ne11` → `nb31/sizeof(half)`) — a live
  garbage-output bug on sm_70 SWA models at depth.
- Sliding-window KV rewritten: sliding layers get their own window-sized cache object, ring
  scan steps over live cells, eviction runs against the earliest still-reachable query
  position, cache sized with allocator slack. This is the fix behind the Rig-A NaN incident.
- `dsa_attn` binds the cuBLAS handle to our stream (upstream race).
- deepseek4 flipped RoPE must not be in-place on sm_70 (`-fa on` aborted).

## 7. Policy changes in this RC

- **All pushes originate on the release host.** No agent harness or sandbox pushes to any remote.
- **One source of truth.** Stray worktrees are not allowed to persist. If work is
  parallelised across agents or worktrees, whoever runs it unifies the result before the
  run counts as done.

Both are recorded in the box handbook (private).

### Build flags removed: `GGML_IQK_MUL_MAT`, `GGML_ALLOW_NO_IQK`

The ik GEMM/flash-attention dispatcher (`iqk_mul_mat.cpp`, `iqk_flash_attn.cpp`) is deleted.
With it goes the option that selected it. This is not a default change — the flag is gone, and
a build script that still passes `-DGGML_IQK_MUL_MAT=OFF` simply gets what it asked for while
`=ON` no longer names anything that exists.

The option could not have survived the deletion. Every one of its 57 call sites is of the form
`if (iqk_x(...)) { fast path }` sitting on top of a stock ggml path, so `OFF` was always
buildable — but with the dispatcher's translation units gone, `ON` is eight undefined
references at link. A flag whose only remaining setting is the one that already happens is a
flag that lies about the choice it offers.

`GGML_ALLOW_NO_IQK` and the `#error` gate it unlocked in `ggml-impl.h` are deleted in the same
commit, deliberately and not as a side effect. That gate fired when the target had neither AVX2
nor ARM dotprod, on the reasoning that the fallback CPU path had rotted unnoticed behind ik and
should not ship silently. After this change **every** target takes that path, AVX2 included, so
the gate can no longer distinguish a risky build from a normal one — its condition
(`GGML_USE_IQK_MULMAT` defined) is now unsatisfiable, and it would have quietly stopped firing
whether or not anyone noticed.

What the gate was standing in for has not gone away, and is now weaker in one specific respect:
the CPU gauntlet used the AVX2 ik build as its reference, so it was measuring *ik versus
no-ik*. With ik gone it compares three no-ik builds against each other and can only see
SIMD-width divergence, not the ik divergence it was built to catch. The last ik-referenced
comparison is preserved at `<local-path>` and the post-deletion AVX2
outputs were diffed against it.

## 9. Unification outcome (the sweep itself)

**245 commits since `v2026.08.11`. Zero branches unmerged.** Engine build **396**, commit `a8fc444`,
built for **sm_60 / sm_61 / sm_70** (the previous `build-safe` was 60;70 only, so the 1080 Ti's
`cc==610` INT8-prefill path was uncovered).

### What the sweep actually found

Most stale branches held **no unique content**. `sm70-stack` (27 commits), `sm70-mmvq` (26),
`wf-P1`/`wf-V` (24 each), `pxa-squash-bak` (1) and `pxa/unified` (9) were each tested three ways —
files present only on the branch, `PXA_*` levers HEAD does not know, defined symbols HEAD lacks —
and all came back empty. Their commits were unreachable only because the same work reached this
line by rebase or cherry-pick into a branch already merged. They are recorded with `merge -s ours`
and **the tree hash was verified byte-identical before and after**.

That mattered, because merging them normally was destructive: `sm70-stack`'s old merge base
produced 68 conflict hunks in which ours was consistently the *later revision of the same code*.
Unioning the "both sides added here" hunks manufactured duplicates — two consecutive
`k_pxq6_gateup_reduce_gen` launches, a second reachable copy of the whole K8-2D split driver, and
duplicate definitions across five files. That is the same damage the abandoned `pxa/unified` union
caused. **Union is right for measurement logs and arch tables; it is wrong for statements.**

### Work that was genuinely lost and is now restored

`pxa-bench/pxq-universal/` — `tier-maps.json`, the three reference budgets (`12g`, `16g`,
`16g-hq`), three `122b-a5b` recipes — plus `examples/quantize/pxqu-presets.h` and
`pxa-tools/kaskal_{pub,old,fixprobe}.py`. The tree's own `.gitignore` states this text ships and
`STRUCTURE.md` points at it, but **no file existed under that path**: `PXQU-CONVERT.md` documented
a `--pxq-universal <map>.tiers` argument with no shipped map to pass it. They survived only on
`pxa-squash-bak`. Restored as files (not by merging that Aug-1 squash, which sits 3,029 files
behind this tree).

### Deliberately not merged

`sm70-codec`'s one unique commit, `0227577` — the K9/K10 decode probes. Both are default-OFF and
**measured slower** (BOOKX −7.2%, MMVX2 −3.4% on a V100); the 187-line body targets the pre-canon
kernel that `PXQ_CANON_v2` replaced. The measurements are recorded in `docs/lab/LEVERS.md` §5 with the
reusable finding (the PXQ decode dot is not shared-memory-bandwidth limited); the kernel bodies are
tagged **`archive/sm70-codec-K9-K10`** so they survive branch pruning.
⚠ `sm70-codec` *reads* as reachable from this line because the abandoned union had merged it — its
code is deliberately absent, and that is not a regression.

### Two conflict resolutions that changed behaviour

- **`pxq_ceiling_check`** (from `ds4-merge-dsa`) refuses a book/SUB16 composition that cannot reach
  the row anchor. Taken verbatim it would `exit(EXIT_FAILURE)` on **every stock PXQ2/PXQ3 quantize**,
  because our retained-for-compat v1 book computes to 0.6970. ds4 could do that having swapped the
  default book; we cannot, because shipped files decode against v1. The frozen v1 table now warns
  and names the lever; any other sub-bar book — including a bad `PXA_PXQ2_BOOK` — still aborts.
  It also got its own `PXQ_CEILING_CHECK_DEFINED` guard: `pxq6-quantize.inc.cpp` is included first
  and wins `PXQ_FIX_GATES_DEFINED`, so a definition placed there from `pxq2` is silently skipped.
- **`PXA_FA_PREFILL_SPLIT`**: `sm70-stack` re-enables auto `=64` for BALANCE mode. The comment both
  sides carry says that path inflates the compute buffer 2.35× (1956→4607 MiB) and OOMs 16 GB cards
  at ub2048 — and every card on this box is 16 GB. Kept opt-in-only.

### Box state

Worktrees **26 → 2** (the repo, detached at the unified tip, plus `<engine-tree>`),
freeing ~20 GB of local disk. Uncommitted content from every pruned worktree is archived at
`<local-path>` (11 tarballs, 24 MB). All four production instances run the unified
engine via `ENGINE_WT`/`ENGINE_BUILD` in an environment file the instance keeper sources, so
cron cannot silently reinstate the old engine.
